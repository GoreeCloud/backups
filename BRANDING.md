## Authority

GoreeCloud product branding is governed by the canonical `GoreeCloud/branding-assets` repository and applicable GoreeCloud branding standards.

## Canonical Identity

The approved GoreeCloud Backups application icon is:

- **Canonical repository:** `GoreeCloud/branding-assets`

- **Product name:** `GoreeCloud Backups`

The former `products/backup/app-icon.svg` path, singular product name, and `GoreeCloud/goreecloud-backup` consumer mapping were superseded and removed from the current canonical branding tree.

## Visual Audit

The approved vector preserves the previously accepted GoreeCloud Backups identity geometry:

- Rounded square application field.
- Green-to-teal gradient.
- High-contrast white repository/storage symbol.
- Recovery/restore arrow that communicates recovery without relying on color alone.
- Accessible SVG title identifying GoreeCloud Backups.

The asset was reviewed at full-size rendering and at 64 px, 32 px, and 16 px raster equivalents. The core storage/recovery silhouette remains recognizable at small sizes; the 32 px rendering remains clear for common launcher and interface contexts, while the 16 px rendering is suitable only where the platform necessarily uses favicon-class dimensions.

## Glaze UI Relationship

The current consumer-eligible Glaze UI authority is **GLAZE UI V1.6 / 1.6.0 Stable**. The Backups identity is compatible with the current GoreeCloud visual language, but branding approval does not establish Backups application-level Glaze UI conformance.

GLAZE UI V1.7 remains Development and is not a consumer-eligible Stable target. Future Backups interface work must adopt the current applicable Stable Glaze release at the time of implementation and complete repository-local rendered, accessibility, motion, performance, and application acceptance.

## Consumer Use

The canonical asset remains in `GoreeCloud/branding-assets`. A repository-local derivative should be added only when Backups gains an implementation surface that requires packaging, launcher, web, manifest, installer, or offline branding resources.

Any consumer copy must record the canonical source and remain synchronized with the verified canonical vector.

## Branding Boundary

The approved icon establishes product identity only. It does not imply:

- Backup-engine implementation.
- Repository implementation.
- Restore capability.
- Recovery verification.
- Runtime health.
- Security or privacy acceptance.
- Glaze UI application conformance.
- Release, deployment, production acceptance, or Stable status.

Operational and acceptance state must be presented independently from branding.
